## 1. Amostragem Metropolis

### 1.1 Motivação e Problema Central

_(pp. 4–5)_

O objetivo central da amostragem Metropolis é construir uma função de densidade de probabilidade (PDF) proporcional a uma função integranda `f(x)`, ou seja, `p(x) ∝ f(x)`.

O método clássico de **inversão** exige o cálculo explícito da integral de normalização:

```
p(x) = f(x) / ∫_Ω f(x) dΩ
```

Essa integral raramente é computável de forma fechada. A **Amostragem Metropolis** contorna esse problema: baseia-se apenas na avaliação pontual de `f(Xᵢ)`, sem necessidade de calcular a normalização. A desvantagem é que requer um número suficiente de amostras iniciais para que a cadeia atinja o equilíbrio da distribuição.

---

### 1.2 Amostragem por Mutação

_(p. 5)_

O algoritmo opera por **mutação sequencial**: dado um estado atual `X`, gera-se um candidato `X'`, e assim sucessivamente. O mecanismo envolve:

- Uma **probabilidade de transição** `T(X → X')` — descreve como o próximo candidato é proposto.
- Uma **probabilidade de aceitação** `a(X → X')` — decide se o candidato é aceito ou se o estado atual é mantido.

---

### 1.3 Propriedade de Balanceamento

_(p. 6)_

Para que a distribuição estacionária da cadeia seja `p(x) ∝ f(x)`, é imposta a condição de **balanceamento detalhado** (_detailed balance_):

```
p(X) · T(X → X') · a(X → X') = p(X') · T(X' → X) · a(X' → X)
```

Substituindo `p(X) = c · f(X)`:

```
f(X) · T(X → X') · a(X → X') = f(X') · T(X' → X) · a(X' → X)
```

Essa equação garante que o fluxo de probabilidade entre dois estados seja simétrico após o equilíbrio.

---

### 1.4 Probabilidade de Aceitação

_(p. 7)_

Para **maximizar a taxa de convergência** ao equilíbrio, a probabilidade de aceitação ótima é:

```
a(X → X') = min( 1,  [f(X') · T(X' → X)] / [f(X) · T(X → X')] )
```

Assumindo que a probabilidade de transição é **simétrica** `T(X → X') = T(X' → X)`, simplifica-se para:

```
a(X → X') = min( 1,  f(X') / f(X) )
```

Consequências práticas:

- Se `f(X') > f(X)` (amostra mais importante), a aceitação é **100%**.
- Se a proposta for rejeitada, a amostra anterior `X` é **reutilizada**.

---

### 1.5 Algoritmos Básicos

_(pp. 8–9)_

**Algoritmo básico (aceitação binária):**

```
X = X₀
for i = 1 to n:
    X' = mutate(X)
    a  = accept(X, X')
    if ξ < a:
        X = X'
    record(X)
```

Limitação: regiões onde `f(x)` é pequeno são dificilmente amostradas.

**Algoritmo por expectativa de valor (pesos fracionários):**

```
X = X₀
for i = 1 to n:
    X' = mutate(X)
    a  = accept(X, X')
    record(X,  1 - a)   ← contribuição do caminho antigo
    record(X', a)        ← contribuição do candidato novo
    if ξ < a:
        X = X'
```

Vantagem: a distribuição converge mais rapidamente, pois ambos os estados contribuem a cada iteração com pesos proporcionais à probabilidade de aceitação.

---

### 1.6 Estratégias de Mutação

_(pp. 10–11)_

A estratégia de mutação pode ser escolhida livremente, desde que a probabilidade de transição `T(X → X')` seja avaliável quando não for simétrica. Dois princípios opostos guiam o projeto:

1. **Mutação deve propor grandes mudanças** — para cobrir o domínio rapidamente.
2. **Mutação deve gerar amostras próximas** — para evitar sequências longas de rejeições e reutilização excessiva (que aumenta variância).

Dois exemplos de mutações **simétricas**:

| Tipo               | Fórmula                  |
| ------------------ | ------------------------ |
| Aleatória (global) | `X' = ξ`                 |
| Vizinhança (local) | `X' = (X ± s·ξ) ∈ [0,1]` |

---

### 1.7 Exemplo Ilustrativo

_(pp. 12–14)_

Para a função `f(x) = (x − 0.5)²` em `[0, 1]`, dois tipos de mutação foram comparados:

- `M₁: X' = ξ` (aleatória)
- `M₂: X' = X + 0.1(ξ − 0.5)` (local)

Conclusões dos histogramas:

- **Apenas M₁**: convergência rápida mas imprecisa; distribuição ruidosa.
- **M₁ (10%) + M₂ (90%)**: melhor equilíbrio — a mutação local explora regiões ricas, enquanto a mutação global evita aprisionamento.
- **Apenas M₂ com 10.000 iterações**: ainda não converge — a cadeia fica presa próxima ao ponto inicial.
- **Apenas M₂ com 300.000 iterações**: converge corretamente, mas muito mais lentamente.

---

### 1.8 Viés do Início da Geração (Warm-up Bias)

_(pp. 15–16)_

O processo de mutação pressupõe que `X₀` já foi amostrado de forma proporcional a `f(x)`. Como isso raramente ocorre na prática, há um **viés transitório** no início da cadeia.

**Solução 1 — Descarte de amostras iniciais (_burn-in_):**

- Descartar as `n` primeiras amostras.
- Desvantagens: custo computacional alto e difícil determinar o valor adequado de `n`.

**Solução 2 — Amostragem auxiliar com peso:**

- Usar outro método para gerar `X₀ ~ p(x)` e associar peso `w = f(X₀) / p(X₀)`.
- Isso elimina o viés, com a restrição de que `f(X₀) ≠ 0`.

**Solução robusta:**

- Gerar `N` candidatos `Y₀, Y₁, ..., Y_{N-1}` via `p(x)`.
- Escolher `X₀` entre os candidatos com probabilidade proporcional a `p(Yᵢ)`.
- O peso `w` é a média dos pesos individuais `wᵢ`.

## 2. Integrador Metropolis

### 2.1 Metropolis Light Transport (MLT)

_(p. 18)_

O MLT aplica a amostragem Metropolis ao problema de **transporte de luz**. É especialmente vantajoso em cenas com iluminação complexa. Os caminhos de luz são gerados por mutações de caminhos anteriores, permitindo exploração local do espaço de caminhos.

Desafio central: aplicar mutações locais em caminhos com reflexões especulares é difícil — modificar um vértice especular pode zerar toda a contribuição do caminho.

> Referência principal: **Kelemen et al. (2002)** — _"A Simple and Robust Mutation Strategy for the Metropolis Light Transport Algorithm"_

---

### 2.2 Formulação da Iluminação Global

_(p. 19)_

A contribuição no pixel `j` via Monte Carlo é:

```
Lⱼ = ∫_P f(z) dz  ≈  (1/M) · Σᵢ [ f(zᵢ) / p(zᵢ) ]
```

onde `zᵢ` representa um caminho completo de transporte de luz e `p(zᵢ)` é a probabilidade de escolha desse caminho.

Idealmente, `p(zᵢ) ∝ f(zᵢ)`. A normalização introduz:

- **Função de contribuição escalar** `I(z)` — por exemplo, a luminância do RGB:  
  `l = 0.299r + 0.587g + 0.114b`
- **Constante de normalização** (brilho médio da cena):  
  `b = ∫_P I(z) dz`
- **PDF normalizada**:  
  `p(z) = I(z) / b`

---

### 2.3 Espaço de Amostragem Primário

_(pp. 20–21)_

A amostragem de caminhos é baseada em **importância local** e **MIS** (_Multiple Importance Sampling_), integrando:

- Amostragem baseada em BRDF
- Amostragem baseada na fonte de luz
- Amostragem de interrupção via **Roleta Russa**

Cada caminho é representado como um vetor de números aleatórios no hipercubo unitário:

```
u = [u₁, u₂, u₃, ...] ∈ U = [0,1]^d
z = S(u)
```

A integral de iluminação pode ser reescrita no espaço primário:

```
Lⱼ = ∫_U f(S(u)) · |dS(u)/du| du
```

O determinante jacobiano satisfaz `|dS(u)/du| = 1 / p_S(u)`, onde `p_S(u)` é a probabilidade do caminho expressa em `U`.

---

### 2.4 Exemplo de Parametrização do Caminho

_(p. 25)_

Um caminho com 8 dimensões tem a seguinte estrutura:

```
u = [u₁, u₂, u₃, u₄, u₅, u₆, u₇, u₈]
```

| Dimensões  | Significado                                      |
| ---------- | ------------------------------------------------ |
| u₁, u₂     | Direção do raio no filme (coordenadas de pixel)  |
| u₃, u₄, u₅ | Roleta Russa e amostra de direção no hemisfério  |
| u₆         | Roleta Russa (evento de interrupção que ocorreu) |
| u₇, u₈     | Amostra de posição na fonte de luz               |

---

### 2.5 Pseudo-código do Integrador

_(pp. 22, 24)_

**Loop de amostragem de caminhos:**

```
for i = 1 to M do:
    Propõe zₜ a partir de zᵢ usando T(zᵢ → zₜ)

    a(zᵢ → zₜ) = min( I(zₜ)·T(zₜ→zᵢ) / I(zᵢ)·T(zᵢ→zₜ) , 1 )

    Seleciona pixel j ao qual zᵢ contribui:
        Φⱼ += (b/M) · (F(zᵢ)/I(zᵢ)) · (1 - a(zᵢ → zₜ))

    Seleciona pixel k ao qual zₜ contribui:
        Φₖ += (b/M) · (F(zₜ)/I(zₜ)) · a(zᵢ → zₜ)

    Gera r ∈ [0,1]
    if r < a(zᵢ → zₜ):  zᵢ₊₁ = zₜ
    else:                 zᵢ₊₁ = zᵢ
```

A contribuição de um caminho individual é:

```
L_zᵢ = (b / M) · f(zᵢ) / I(zᵢ)
```

---

### 2.6 Ajustes Práticos para Traçado de Caminhos

_(p. 23)_

Para inicializar a cadeia de forma adequada:

1. **Gerar várias sementes** `z` e estimar `b = ∫ I(z) dz`.
2. **Escolher z₀** entre as sementes com probabilidade proporcional a `I(z)` — garante início em região relevante.
3. **Usar amostras não aceitas** com peso proporcional à taxa de aceitação — aproveita toda iteração.

---

### 2.7 Combinação de Mutações via MIS

_(pp. 26–27)_

Duas estratégias de mutação são combinadas:

| Estratégia                 | Descrição                                 | Probabilidade da PDF   |
| -------------------------- | ----------------------------------------- | ---------------------- |
| **Mutação pequena** (`M₁`) | Perturbação local; `M₁` amostras          | `p₁(u) = I(u)/b`       |
| **Mutação grande** (`M₂`)  | Caminho completamente novo; `M₂` amostras | `p₂(u) = 1` (uniforme) |

Relação entre os tamanhos dos lotes:

```
M₂ = p_large · M,   com   M = M₁ + M₂
```

Via **MIS**, o peso de cada amostra é:

```
w(u) = 1 / [M₁ · p₁(u) + M₂ · p₂(u)]
```

Contribuições combinadas por tipo de mutação:

- **Caminho antigo (rejeitado):**  
  `(1-a) · w(u) · f(u) = (1-a) · f(u) / [(I(u)/b + p_large) · M]`

- **Mutação pequena (aceita):**  
  `a · w(u) · f(u) = a · f(u) / [(I(u)/b + p_large) · M]`

- **Mutação grande (Metropolis + não correlacionada simultaneamente):**  
  `(a+1) · f(u) / [(I(u)/b + p_large) · M]`

---

### 2.8 Geração de Caminhos com Comprimento Variável

_(pp. 28–29)_

Caminhos podem ser **encurtados** ou **aumentados** via Roleta Russa. Quando um caminho é encurtado e posteriormente reexpandido, as amostras `uᵢ` anteriores são **reaproveitadas** — reduzindo descontinuidades e aumentando coerência estatística.

Em contextos bidirecionais, é importante **não misturar** as dimensões `uᵢ` associadas ao subcaminho da câmera com as do subcaminho da fonte de luz.

**Pseudocódigo da mutação local:**

```
i = índice aleatório da amostragem primária

δ = s₂ · exp(−log(s₂/s₁) · ξ₂),   com δ ∈ [s₁, s₂]

if ξ₃ < 0.5:
    uᵢ = uᵢ + δ
else:
    uᵢ = uᵢ − δ
```

Valores típicos recomendados: `s₁ = 1/1024`, `s₂ = 1/64`.

## 4. Síntese dos Conceitos

| Conceito                            | Descrição                                                         |
| ----------------------------------- | ----------------------------------------------------------------- |
| **PDF Metropolis**                  | `p(x) ∝ f(x)` construída sem normalização explícita               |
| **Cadeia de Markov**                | Navegação correlacionada no espaço de caminhos                    |
| **Balanceamento detalhado**         | Garante distribuição estacionária correta                         |
| **Critério de Metropolis-Hastings** | `a = min(1, f(X')·T(X'→X) / f(X)·T(X→X'))`                        |
| **Espaço primário**                 | Caminhos representados como vetores `u ∈ [0,1]^d`                 |
| **Bootstrap / Warm-up**             | Escolha de `z₀` proporcional a `I(z)` para inicialização sem viés |
| **Mutação pequena**                 | Perturbação local; explora vizinhança de caminhos promissores     |
| **Mutação grande**                  | Caminho totalmente novo; escapa de máximos locais                 |
| **MIS para mutações**               | Combinação ótima das duas estratégias via pesos balanceados       |
| **Multiplexed MLT**                 | Versão final com múltiplas estratégias integradas                 |
